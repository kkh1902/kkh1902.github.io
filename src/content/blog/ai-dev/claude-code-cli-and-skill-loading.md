## 자주 쓰는 명령어

`claude`로 대화형 세션을 시작하는 것 말고도 알아두면 편한 명령어가 몇 개
있다.

- `claude -p "query"` — SDK처럼 한 번 질의하고 바로 종료. 스크립트나
  파이프에 연결할 때 쓴다.
- `claude -c` / `claude -r "<session>"` — 최근 대화를 이어가거나 특정
  세션을 다시 연다. 세션 이름을 기억해두면 나중에 찾기 쉽다.
- `claude agents` — 여러 백그라운드 세션을 한 화면에서 모니터링하는
  에이전트 뷰를 연다.

자주 쓰는 플래그는 다음과 같다.

- `--model` — sonnet/opus/haiku 별칭으로 모델을 바로 지정.
- `--permission-mode` — default/acceptEdits/plan/auto 중 하나를 시작
  시점부터 고정. 반복 작업을 자동화할 때 유용하다.
- `--worktree` — 격리된 git worktree에서 세션을 시작해 다른 작업과
  파일 충돌을 피한다.
- `--append-system-prompt` — 시스템 프롬프트를 통째로 바꾸지 않고
  일부만 덧붙인다. 작은 행동 하나만 바꾸고 싶을 때 전체 교체보다 안전하다.

## 스킬이 안 보일 때

커스텀 커맨드(`~/.claude/commands/<이름>.md`)나 프로젝트 스킬
(`.claude/skills/<이름>/SKILL.md`)을 새로 만들었는데 세션에서 안 보여서
당황한 적이 있다면, 원인은 대개 하나다 — **스킬·커맨드 목록은 세션이
시작할 때 딱 한 번만 읽힌다.** 세션 도중에 새로 추가해도 그 세션 안에서는
반영되지 않는다. `/clear`로 새 세션을 시작하거나 재시작해야 보인다.

또 하나 헷갈리는 부분은 범위다. 프로젝트 스킬은 저장소 안에 있어서 git으로
같이 공유되지만, 전역 스킬·커맨드(`~/.claude/` 아래)는 git 관리 밖이라
기기마다 따로 둬야 한다. 노트북에서 만든 전역 스킬이 데스크톱에는 없는
게 당연한 이유다.

## 정리

CLI 플래그는 몰라도 기본 대화로 웬만한 건 다 된다. 다만 반복 작업을
자동화하거나 여러 세션을 동시에 돌릴 계획이라면 위 몇 개만 알아둬도
설정 삽질이 크게 줄어든다. 스킬이 안 먹힐 땐 코드를 의심하기 전에
"새 세션으로 다시 시작했는가"부터 확인하는 습관을 들이면 된다.
