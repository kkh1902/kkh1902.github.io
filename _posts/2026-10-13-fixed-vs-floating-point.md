## TL;DR

고정소수점은 "소수점 위치를 자로 미리 그어놓고 쓰는 것", 부동소수점은 "소수점을 과학적
표기법(가수×2^지수)처럼 떠다니게 해서 넓은 범위를 표현하는 것"이다. 대부분의 프로그램은
부동소수점(`float`/`double`)을 쓰지만, 그 대가로 0.1 + 0.2 ≠ 0.3 같은 오차가 생긴다.

## 비유 한 줄

고정소수점 = 자(ruler)에 눈금을 미리 새겨둔 것(범위는 좁지만 간격은 균일). 부동소수점 =
돋보기를 들고 필요한 배율로 당겨 보는 것(아주 작은 수도 아주 큰 수도 다 보이지만, 배율이
바뀔 때마다 미세한 오차가 생김).

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| 고정소수점(Fixed Point) | 미리 그어둔 눈금자 | 정수부·소수부 비트 수를 고정해 표현. 단순하지만 표현 범위가 좁음 |
| 부동소수점(Floating Point) | 배율 조절 돋보기 | 부호·지수(exponent)·가수(mantissa)로 구성, 지수가 소수점 위치를 "움직임" — IEEE 754 표준 |
| 가수(Mantissa) | 실제 숫자 모양 | 유효숫자를 저장하는 부분 (예: 1.23×10²에서 "1.23") |
| 지수(Exponent) | 배율(10의 몇 승) | 소수점을 몇 자리 옮길지 결정 (예: 1.23×10²에서 "2") |
| 부동소수점 오차 | 돋보기 배율이 딱 안 맞음 | 2진수로는 0.1 같은 수를 정확히 표현 못 해 반올림 오차가 누적됨 |

## 구조 다이어그램

```
[고정소수점, 예: 정수부 16bit + 소수부 16bit]
  부호 | 정수부(16bit) | 소수부(16bit)
  → 표현 범위 고정, 계산 빠르고 단순, but 큰 수/작은 수 둘 다 못 담음

[부동소수점, IEEE 754 단정도(32bit)]
  부호(1bit) | 지수(8bit) | 가수(23bit)
  → 값 = (-1)^부호 × 1.가수 × 2^(지수-127)
  → 지수로 "소수점을 옮겨가며" 아주 크거나 아주 작은 수까지 표현
```

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 고정소수점은 범위가 좁은가? | 정수부·소수부 비트가 못 박혀 있어서. 32bit를 16/16으로 나누면 정수부 최대값이 약 6만대로 제한됨 |
| 왜 부동소수점이 넓은 범위를 표현하나? | 지수부가 "소수점 위치"를 결정하므로, 같은 비트 수로도 지수 조절만으로 아주 큰 수(10^38)와 아주 작은 수(10^-38)를 둘 다 표현 가능 |
| 왜 0.1 + 0.2가 0.3이 아닌가? | 0.1, 0.2는 2진수로 정확히 떨어지지 않는 무한소수(1/10, 1/5는 2의 거듭제곱 분모가 아님) → 가수 23/52bit에서 반올림되어 미세한 오차가 생기고, 덧셈 과정에서 그 오차가 그대로 드러남 |
| 임베디드·DSP는 왜 지금도 고정소수점을 쓰는가? | 부동소수점 전용 하드웨어(FPU)가 없거나 비싼 환경(저전력 마이크로컨트롤러)에서는 정수 연산만으로 처리 가능한 고정소수점이 더 빠르고 예측 가능함(실시간 시스템은 연산 시간이 일정해야 함) |
| 돈 계산에 float를 쓰면 안 되는 이유는? | 부동소수점 오차가 누적되면 금액이 조금씩 어긋날 수 있음 — 대신 정수(원 단위) 또는 고정소수점형 `decimal` 타입을 사용 |

## 예시

```python
print(0.1 + 0.2)          # 0.30000000000000004  — 부동소수점 오차
print(0.1 + 0.2 == 0.3)   # False

from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2"))  # 0.3  — 고정 자리수(10진수) 연산이라 정확
```

파이썬의 `float`는 내부적으로 IEEE 754 double(64bit)을 쓰고, `Decimal`은 10진수 기반
고정 자리수 연산을 흉내 낸 타입이라 금액 계산 같은 곳에 쓰인다.

## 요약 표

| 구분 | 고정소수점 | 부동소수점 |
|---|---|---|
| 구성 | 부호 + 정수부 + 소수부(비트 고정) | 부호 + 지수 + 가수 |
| 장점 | 단순, 연산 빠름, 정밀도 균일 | 표현 범위 매우 넓음 |
| 단점 | 범위 좁음 | 정밀도 오차 발생 |
| 대표 사용처 | 임베디드, DSP, 실시간 시스템, 금액 계산(`decimal`) | 일반 프로그래밍 언어의 `float`/`double`, 과학 연산 |
