## TL;DR

DP는 "한 번 푼 문제는 답을 적어두고 다시는 안 푸는 것"이다. 똑같은 작은 문제가
여러 번 반복해서 등장할 때(겹치는 부분 문제), 결과를 저장(메모이제이션)해뒀다가
재사용하면 지수 시간(O(2ⁿ))이 걸리던 문제를 다항 시간으로 줄일 수 있다.

## 비유 한 줄

피보나치수열을 손으로 계산할 때 `fib(5)`를 구하려고 `fib(3)`을 두 번, 세 번 다시
계산하는 대신 — 한 번 구한 `fib(3)` 값을 포스트잇에 적어두고 다음에 또 필요하면
포스트잇만 보는 것.

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| 겹치는 부분 문제(Overlapping Subproblems) | 같은 계산을 여러 번 반복 | 큰 문제를 쪼갠 작은 문제들이 서로 겹쳐서 중복 계산이 발생 |
| 최적 부분 구조(Optimal Substructure) | 부분의 최적 답을 합치면 전체 최적 답 | 작은 문제의 최적해로 큰 문제의 최적해를 구성할 수 있는 성질 |
| 메모이제이션(Memoization) | 포스트잇에 답 적어두기 | 재귀 + 캐시(top-down) — 이미 계산한 값은 저장해두고 재사용 |
| 타뷸레이션(Tabulation) | 표를 밑에서부터 채워 올라가기 | 반복문 + 배열(bottom-up) — 작은 문제부터 순서대로 표를 채움 |

## 구조 다이어그램

```
[메모이제이션 없는 피보나치] — fib(5) 호출 트리, 중복 계산 多
                      fib(5)
                  /           \
             fib(4)           fib(3)
            /      \          /    \
       fib(3)    fib(2)   fib(2)  fib(1)   ← fib(3), fib(2)가 여러 번 재계산됨
       /    \
   fib(2)  fib(1)

[메모이제이션 적용] — 한 번 계산한 값은 캐시에서 바로 꺼냄
   fib(5) → fib(4) → fib(3) → fib(2) → fib(1), fib(0)   (각각 딱 1번만 계산)
```

## 동작 원리(왜?)

| 질문 | 답 |
|---|---|
| 왜 DP는 두 조건(겹치는 부분 문제 + 최적 부분 구조)이 둘 다 필요한가? | 겹치는 부분 문제가 없으면 캐싱할 게 없어 그냥 분할정복과 같고, 최적 부분 구조가 없으면 부분 답을 합쳐도 전체 최적이 보장 안 돼서 DP 테이블 자체가 의미 없어짐 |
| Top-down과 Bottom-up 중 뭐가 더 나은가? | 정답은 없음 — Top-down(재귀+메모)은 필요한 부분문제만 계산해 직관적이지만 재귀 호출 오버헤드가 있고, Bottom-up(반복문+테이블)은 전체를 다 채우지만 빠르고 스택 오버플로 위험이 없음 |
| 그리디(Greedy)와 뭐가 다른가? | 그리디는 매 순간 최선의 선택만 하고 되돌아보지 않는데, 그 선택이 전체 최적을 보장 못 할 수 있음(반례 존재). DP는 모든 부분 문제의 답을 비교해서 전체 최적을 보장 |
| 코테에서 DP 문제를 알아보는 신호는? | "최댓값/최솟값/경우의 수를 구하라" + "이전 상태에 따라 현재 선택이 달라진다"는 조건이 같이 나오면 DP를 의심 (배낭 문제, 최장 증가 부분수열, 계단 오르기 등) |

## 예시

```python
# Top-down (메모이제이션)
from functools import lru_cache

@lru_cache(maxsize=None)
def fib_memo(n):
    if n <= 1:
        return n
    return fib_memo(n - 1) + fib_memo(n - 2)

# Bottom-up (타뷸레이션)
def fib_table(n):
    dp = [0, 1] + [0] * (n - 1)
    for i in range(2, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]

print(fib_memo(30))   # 832040, O(n)
print(fib_table(30))  # 832040, O(n)
```

## 요약 표

| 방식 | 구현 | 장점 | 단점 |
|---|---|---|---|
| 메모이제이션(Top-down) | 재귀 + 캐시(dict/lru_cache) | 필요한 부분만 계산, 코드가 재귀적으로 직관적 | 재귀 깊이 제한, 함수 호출 오버헤드 |
| 타뷸레이션(Bottom-up) | 반복문 + 배열 | 빠름, 스택 오버플로 없음 | 전체 테이블을 다 채워야 해서 메모리 낭비 가능 |
