## TL;DR

PCB(Process Control Block)는 프로세스의 "신상카드"다 — 이 프로세스가 지금 뭘 하고 있었는지
전부 적혀 있다. 컨텍스트 스위칭은 교대 근무자끼리 "바통 터치"하는 것 — 지금 일하던 사람의
신상카드에 현재 상태를 적어 넣고, 다음 사람의 신상카드를 펼쳐 그 상태 그대로 이어서 일한다.

## 비유 한 줄

PCB = 직원 개인 신상카드(지금 몇 번째 업무를 하고 있는지, 어떤 자료를 들고 있는지 전부 기록),
컨텍스트 스위칭 = 교대 시간에 신상카드를 서랍에 넣고 다음 사람 카드를 꺼내는 행위.

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| PCB(Process Control Block) | 직원 신상카드 | OS가 프로세스마다 유지하는 상태 정보 구조체 |
| PID | 사원번호 | 프로세스를 구분하는 고유 식별자 |
| PC(Program Counter) | 지금 읽던 페이지 번호 | 다음에 실행할 명령어 주소 |
| 레지스터 값 | 손에 쥔 메모지 | CPU 레지스터의 현재 값, 복귀 시 그대로 복원 |
| 프로세스 상태 | 근무 상태(근무중/대기중/대기줄) | New/Ready/Running/Waiting/Terminated |
| 메모리 관리 정보 | 사무실 호실 번호 | 베이스/리밋 레지스터, 페이지 테이블 포인터 등 |
| 컨텍스트 스위칭 | 교대 근무 바통터치 | 실행 중인 프로세스 상태를 PCB에 저장하고 다음 프로세스 PCB를 복원하는 과정 |

## 구조 다이어그램

```
[New] → [Ready 큐] ⇄ [Running] → [Terminated]
            ▲             │
            │             ▼
          [Waiting] (I/O, 이벤트 대기)

컨텍스트 스위칭 순간:
[Running: 프로세스 A] --- 타이머 인터럽트 ---> [A의 PCB에 현재 레지스터/PC 저장]
                                                      │
                                              [스케줄러가 Ready 큐에서 B 선택]
                                                      │
                                              [B의 PCB에서 레지스터/PC 복원]
                                                      ▼
                                           [Running: 프로세스 B 실행 시작]
```

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 컨텍스트 스위칭이 "비용"으로 취급되나? | 레지스터 저장/복원뿐 아니라 CPU 캐시·TLB가 새 프로세스 메모리로 다시 채워져야 해서(캐시 미스 증가) 실질 계산 시간이 줄어듦 |
| 왜 PCB는 커널 메모리에 있나? | 유저 프로그램이 직접 건드리면 다른 프로세스 상태를 조작할 수 있어 보안 문제 — 커널만 접근 가능 |
| 왜 스레드 전환은 더 가벼운가? | 같은 프로세스 내 스레드는 코드·데이터·힙·메모리 매핑(페이지 테이블)을 공유해서 그 부분을 안 바꿔도 됨 — 레지스터·스택·PC만 바꾸면 끝 |
| 컨텍스트 스위칭은 언제 발생하나? | 타이머 인터럽트(타임 슬라이스 소진), I/O 요청으로 Waiting 전환, 더 높은 우선순위 프로세스 등장, 시스템 콜 완료 등 |

## 예시

```c
// 개념을 보여주는 의사코드 — 실제 OS 커널 switch() 흐름
void context_switch(PCB *current, PCB *next) {
    save_registers(current);      // 현재 레지스터 -> current->registers
    current->state = READY;

    next->state = RUNNING;
    restore_registers(next);      // next->registers -> CPU 레지스터
    set_program_counter(next->pc);
}
```

리눅스에서 `ps -eo pid,stat,pcpu,cmd`로 보이는 상태(R, S, D 등)가 바로 PCB의 프로세스
상태 필드를 사람이 읽을 수 있게 보여주는 것이다.

## 요약 표

| 항목 | 내용 |
|---|---|
| PCB에 담기는 것 | PID, 상태, PC, 레지스터, 메모리 정보, 열린 파일 목록, 스케줄링 우선순위 |
| 컨텍스트 스위칭 트리거 | 타이머 인터럽트, I/O 대기, 우선순위 선점, 시스템 콜 완료 |
| 비용의 원인 | 레지스터 저장/복원 자체는 작지만, 캐시·TLB 재적재 비용이 큼 |
| 줄이는 방법 | 타임 슬라이스를 적절히 크게, 멀티스레드로 전환 비용 자체를 줄이기 |
