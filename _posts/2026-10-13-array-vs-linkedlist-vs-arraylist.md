## TL;DR

배열은 "번호가 매겨진 사물함 줄", 연결리스트는 "앞뒤로 이어진 기차 칸"이다. 배열은 번호로
바로 찾아가지만(O(1)) 줄 중간에 칸을 끼워 넣기 어렵고, 연결리스트는 중간 삽입/삭제는
쉽지만(O(1)) 몇 번째 칸인지 찾으려면 앞에서부터 세며 가야 한다(O(N)). ArrayList는 배열을
기반으로 삼되 꽉 차면 더 큰 사물함 줄로 "이사"해서 크기 제약을 극복한 절충안이다.

## 비유 한 줄

배열 = 번호판 붙은 사물함이 일렬로 붙어 있는 줄(인덱스로 즉시 접근, 중간에 새 사물함을
끼우려면 뒤 칸을 전부 밀어야 함). 연결리스트 = 손을 잡고 서 있는 기차 칸들(중간에 끼어들긴
쉽지만, 몇 번째 칸인지 알려면 앞 칸부터 손을 따라가야 함).

## 개념 표

| 자료구조 | 비유 | 한줄 설명 |
|---|---|---|
| 배열(Array) | 번호 붙은 사물함 줄 | 연속된 메모리 공간, 인덱스로 O(1) 접근, 크기 고정 |
| 연결리스트(LinkedList) | 손잡고 서 있는 기차 칸 | 각 노드가 다음(이전) 노드 주소를 가짐, 메모리 비연속, 크기 가변 |
| ArrayList | 꽉 차면 더 큰 줄로 이사하는 사물함 | 내부는 배열, 용량 초과 시 보통 1.5~2배 큰 새 배열로 복사 — 동적 배열 |
| 포인터(노드 연결) | 기차 칸 사이 손잡이 | 다음 칸 주소를 저장하는 참조값, 이게 있어서 메모리가 흩어져 있어도 순회 가능 |

## 구조 다이어그램

```
[배열]                              [연결리스트]
idx: 0    1    2    3               [10|next] → [20|next] → [30|next] → null
val: 10   20   30   40              (메모리상 흩어져 있고, 각 노드가 다음 주소를 들고 있음)
(메모리상 연속, 주소 = base + idx*size)

[ArrayList 용량 초과 시]
[10][20][30][40]  ← 꽉 참
     ↓ 새 배열(보통 2배 크기) 할당 후 전체 복사
[10][20][30][40][ ][ ][ ][ ]  ← 이후 삽입은 빈 칸에
```

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 배열은 접근이 O(1)인가? | 메모리가 연속이라 `base_address + index × 요소크기` 계산 한 번으로 바로 주소를 구할 수 있음(점프 가능) |
| 왜 연결리스트는 접근이 O(N)인가? | 메모리가 흩어져 있어 주소를 계산으로 못 구함 — 몇 번째인지 알려면 처음(또는 특정 지점)부터 next를 따라가야 함 |
| 왜 연결리스트는 중간 삽입이 O(1)인가? | 앞뒤 칸을 밀 필요 없이, 끼워 넣을 위치의 앞 노드가 가진 주소(포인터)만 바꿔 끼우면 되기 때문(단, 그 위치를 찾는 데는 O(N)이 걸릴 수 있음) |
| 왜 배열은 중간 삽입이 O(N)인가? | 중간에 자리를 만들려면 그 뒤의 모든 요소를 한 칸씩 뒤로 밀어야 함 |
| ArrayList는 왜 "크기 2배"로 늘리나? | 매번 1칸씩 늘리면 삽입마다 복사가 발생해 O(N²)이 되지만, 배수로 늘리면 복사 횟수가 로그 수준으로 줄어 삽입의 평균(amortized) 비용이 O(1)이 됨 |
| LinkedList는 언제 유리한가? | 삽입/삭제가 잦고 접근은 순차적인 경우(예: 큐, 덱) — 반대로 랜덤 접근이 잦으면 배열/ArrayList가 압도적으로 유리 |

## 예시

```java
// ArrayList: 인덱스 접근 빠름(O(1)), 중간 삽입 느림(O(N))
List<Integer> arr = new ArrayList<>();
arr.add(10); arr.add(20); arr.add(30);
arr.get(1);              // O(1) — 바로 주소 계산
arr.add(1, 99);          // O(N) — 뒤 요소들 한 칸씩 밀기

// LinkedList: 중간 삽입 빠름(위치만 알면 O(1)), 인덱스 접근 느림(O(N))
List<Integer> list = new LinkedList<>();
list.add(10); list.add(20); list.add(30);
list.get(1);             // O(N) — 앞에서부터 next를 따라가야 함
```

## 요약 표

| 연산 | 배열(Array) | ArrayList | LinkedList |
|---|---|---|---|
| 인덱스 접근 | O(1) | O(1) | O(N) |
| 끝에 추가 | O(1) (고정 크기 한계) | O(1) 평균(가끔 O(N) 리사이즈) | O(1) |
| 중간 삽입/삭제 | O(N) | O(N) | O(1) (위치를 안다면) |
| 크기 | 고정 | 가변 | 가변 |
| 메모리 | 연속, 오버헤드 적음 | 연속, 오버헤드 적음 | 비연속, 노드마다 포인터 오버헤드 |
