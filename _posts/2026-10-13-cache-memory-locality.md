## TL;DR

캐시는 "자주 쓰는 물건을 책상 위에 꺼내두는 것"이다. CPU가 메모리(창고)까지 매번 가지러 가면
느리니, 최근에 쓴 데이터와 그 근처 데이터를 미리 책상(캐시)에 꺼내둔다. 이게 가능한 이유는
프로그램이 실제로 "방금 쓴 걸 또 쓰고, 옆에 있는 걸 또 쓰는" 습관(지역성)을 갖기 때문이다.

## 비유 한 줄

책상(L1 캐시, 빠르지만 좁음) → 책장(L2/L3 캐시) → 창고(메인 메모리, 크지만 느림) 순서로
데이터를 찾는다. 책상에 있으면 바로 쓰고(Cache Hit), 없으면 책장·창고까지 가서 가져오며
가는 김에 옆 자료도 같이 들고 온다(Cache Miss + 공간 지역성).

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| 시간 지역성(Temporal Locality) | 방금 편 책을 또 편다 | 최근 참조된 데이터가 곧 다시 참조될 가능성이 높음 (예: 반복문의 카운터 변수) |
| 공간 지역성(Spatial Locality) | 옆 페이지도 미리 펴둔다 | 참조된 주소 근처 데이터가 곧 참조될 가능성이 높음 (예: 배열 순차 접근) |
| Cache Hit / Miss | 책상에 있다 / 없다 | 캐시에서 찾으면 Hit(빠름), 없어서 메인 메모리까지 가면 Miss(느림) |
| L1 / L2 / L3 캐시 | 책상 / 책장 / 사무실 공용 서랍 | 코어에 가까울수록 빠르고 작음(L1), 멀수록 크고 느림(L3, 코어 간 공유) |
| 캐시 라인(Cache Line) | 한 번에 책 한 챕터씩 옮기기 | 캐시는 1바이트가 아니라 보통 64바이트 블록 단위로 데이터를 통째로 옮김 — 공간 지역성을 활용하기 위함 |

## 구조 다이어그램

```
[CPU 코어] → [L1 캐시, 코어 전용, ~수십KB]
                  ↓ miss
             [L2 캐시, 코어 전용 또는 공유, ~수백KB~수MB]
                  ↓ miss
             [L3 캐시, 전체 코어 공유, ~수십MB]
                  ↓ miss
             [메인 메모리(RAM), GB 단위, 훨씬 느림]
```

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 캐시는 작게 만드는가? | 캐시는 SRAM(비싸고 빠름)을 쓰고 메모리는 DRAM(싸고 느림)을 씀 — 속도와 용량·비용은 트레이드오프라 작게 만들 수밖에 없음 |
| 왜 "근처 데이터"까지 같이 가져오는가? | 공간 지역성 때문. 배열을 순회하는 코드처럼 실제 프로그램은 근처 주소를 연달아 접근하는 패턴이 압도적으로 많아서, 미리 당겨오면 다음 접근이 대부분 Hit가 됨 |
| 왜 반복문이 빠른 이유 중 하나가 캐시인가? | 반복문 조건 변수(`i`)는 매 루프 재사용(시간 지역성), 배열 접근은 순차적(공간 지역성) — 두 지역성이 동시에 성립해 캐시 효율이 매우 높음 |
| 왜 2차원 배열 접근 순서가 성능에 영향을 주는가? | `arr[i][j]`를 행(row) 우선으로 순회하면 메모리상 연속된 주소를 따라가 공간 지역성이 유지되지만, 열(column) 우선으로 돌면 매번 캐시 라인을 벗어나 Miss가 급증함 |
| 왜 멀티코어는 L1을 코어마다 따로 두는가? | 코어 간 경합 없이 각자 빠르게 접근하기 위함. 대신 L2/L3는 공유해 전체 캐시 효율과 비용 균형을 맞춤 |

## 예시

```c
// 공간 지역성을 살리는 순회 (행 우선, 캐시 친화적)
for (int i = 0; i < N; i++)
    for (int j = 0; j < N; j++)
        sum += arr[i][j];   // 메모리상 연속 접근 → Cache Hit 많음

// 공간 지역성을 깨는 순회 (열 우선, 캐시 비친화적)
for (int j = 0; j < N; j++)
    for (int i = 0; i < N; i++)
        sum += arr[i][j];   // 매번 캐시 라인 밖 주소 접근 → Cache Miss 많음
```

N이 커질수록 두 코드의 실행 시간 차이가 몇 배씩 벌어진다 — 알고리즘 복잡도는 같아도
"캐시를 얼마나 잘 쓰는가"가 실제 체감 속도를 좌우하는 대표적인 예다.

## 요약 표

| 구분 | 특징 |
|---|---|
| 지역성의 근거 | 시간 지역성(최근 쓴 걸 또 씀) + 공간 지역성(근처를 또 씀) |
| 캐시 계층 | L1(코어 전용, 최速) → L2 → L3(공유, 메모리보다는 빠름) |
| Hit/Miss | Hit=캐시에서 바로, Miss=메인 메모리까지 가서 캐시 라인 단위로 적재 |
| 실전 팁 | 배열은 메모리 저장 순서(행 우선)대로 순회해야 캐시 효율이 올라감 |
