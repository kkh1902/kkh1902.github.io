## TL;DR

인터럽트는 "전화벨"이다 — CPU가 일하다가 외부(하드웨어) 신호가 오면 하던 일을 멈추고 전화를
받는다. 시스템 콜은 그 전화 중에서도 "내가 직접 거는 전화"다 — 사용자 프로그램이 커널에게
"파일 좀 열어줘" 같은 요청을 할 때 의도적으로 발생시키는 소프트웨어 인터럽트(트랩)다.

## 비유 한 줄

인터럽트 = 일하다 걸려오는 전화(키보드 입력, 타이머, 디스크 완료 신호 등 외부에서 거는 것),
시스템 콜 = 안내데스크(커널)에 내가 직접 가서 요청하는 것(단, 보안상 창구 너머로는 못 들어가고
반드시 안내데스크를 거쳐야 함).

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| 인터럽트(Interrupt) | 걸려오는 전화 | 하드웨어/소프트웨어가 CPU에게 "지금 당장 처리해줘"라고 보내는 신호 |
| 하드웨어 인터럽트 | 외부에서 온 전화 | 키보드, 타이머, 디스크 I/O 완료 등 주변장치가 발생시킴 |
| 소프트웨어 인터럽트(Trap) | 내가 거는 전화 | 프로그램 실행 중 예외 상황이나 시스템 콜 요청으로 발생 |
| 시스템 콜(System Call) | 안내데스크 요청 | 사용자 모드 프로그램이 커널 모드 기능(파일, 메모리, 프로세스)을 쓰는 유일한 공식 통로 |
| ISR(Interrupt Service Routine) | 전화 받는 매뉴얼 | 인터럽트 종류별로 정해진 처리 루틴 |
| 인터럽트 벡터(Vector) | 전화번호부 | 인터럽트 번호 → ISR 주소를 매핑한 테이블 |
| 유저 모드 / 커널 모드 | 손님 구역 / 직원 전용 구역 | CPU 권한 레벨 구분, 시스템 콜·트랩만 이 경계를 공식적으로 넘나듦 |

## 구조 다이어그램

```
[사용자 프로그램]  read() 호출
      │
      ▼
[시스템 콜 = 소프트웨어 인터럽트 발생] ── 유저 모드 → 커널 모드 전환
      │
      ▼
[인터럽트 벡터 테이블 조회] → 해당 ISR 주소 찾기
      │
      ▼
[커널: 시스템 콜 핸들러 실행] (실제 디스크 읽기 등 수행)
      │
      ▼
[레지스터 복원 + 커널 모드 → 유저 모드 전환]
      │
      ▼
[사용자 프로그램 재개] (read() 반환값 받음)
```

하드웨어 인터럽트는 이 흐름의 시작점이 사용자 코드가 아니라 외부 장치라는 점만 다르고,
"현재 실행 멈춤 → 모드 전환 → ISR 실행 → 복귀"라는 뼈대는 동일하다.

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 시스템 콜이 함수 호출이 아니라 인터럽트로 구현되나? | 유저 모드 코드가 커널 메모리·하드웨어를 직접 건드리면 보안·안정성이 깨짐. 트랩을 걸어 CPU 권한 자체를 커널 모드로 바꾼 뒤에만 민감한 작업을 허용 |
| 왜 인터럽트가 발생하면 레지스터 상태를 저장하나? | 처리가 끝나면 원래 하던 작업으로 정확히 복귀해야 하기 때문 — PCB에 저장되는 정보와 겹치는 이유 |
| 왜 인터럽트에 우선순위(마스킹)가 있나? | 타이머 인터럽트 처리 중에 또 타이머가 울리는 식의 재진입 문제를 막고, 더 급한 신호(전원 차단 등)를 먼저 처리하기 위해 |
| 왜 같은 시스템 콜인데 블로킹/논블로킹이 갈리나? | 커널이 요청을 즉시 처리할 수 있는지(논블로킹) 아니면 디스크 I/O처럼 기다려야 하는지(블로킹, 프로세스를 대기 상태로 전환)에 따라 다름 |

## 예시

```python
import os

# read()는 겉보기엔 평범한 함수지만, 내부에서 시스템 콜을 발생시킨다.
fd = os.open("example.txt", os.O_RDONLY)
data = os.read(fd, 1024)  # 여기서 소프트웨어 인터럽트(트랩) 발생 -> 커널 모드 진입
os.close(fd)

# 리눅스에서 strace python3 script.py 로 실행하면
# open/read/close가 실제 시스템 콜로 찍히는 걸 확인할 수 있다.
```

## 요약 표

| 항목 | 인터럽트 | 시스템 콜 |
|---|---|---|
| 발생 주체 | 하드웨어(주로) + 소프트웨어 | 사용자 프로그램(의도적) |
| 목적 | CPU에게 즉시 처리할 이벤트 알림 | 유저 모드가 커널 기능을 안전하게 요청 |
| 분류상 관계 | 더 넓은 개념 | 소프트웨어 인터럽트(트랩)의 한 종류 |
| 공통점 | 둘 다 모드 전환 + 레지스터 저장/복원 + 벡터 테이블 조회를 거침 | |
