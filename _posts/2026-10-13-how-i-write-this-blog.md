## 한 줄 결론

이 블로그 글은 전부 "비유 → 표 → 다이어그램" 순서로 쓴다 — 긴 설명 문단보다 눈으로
한 번에 들어오는 구조를 우선한다.

## 왜 이렇게 쓰나

비유로 그림이 먼저 그려져야 이해가 되는 편이고, 호기심이 많아서 한 개념을 깊게
파고드는 편이다. 그런데 깊이를 긴 문장으로 풀면 오히려 못 읽는다 — 그래서 "깊이는
유지하되 분량은 압축"하는 방법으로 표와 다이어그램을 쓴다.

## 글 구조

| 순서 | 섹션 | 역할 |
|---|---|---|
| 1 | 한 줄 결론 | 왜 읽는지 먼저 |
| 2 | 비유 | 개념을 일상 언어로 압축 |
| 3 | 개념 표 | 용어·비유·설명을 한 표로 |
| 4 | 구조 다이어그램 | `[A] → [B]` 텍스트 박스로 흐름 시각화 |
| 5 | 동작 원리 | "왜 이렇게 동작하나"를 짧게 |
| 6 | 최소 예시 | 코드/실습 1개만 |
| 7 | 요약 표 | 전체 내용을 표 하나로 다시 압축 |

## 다이어그램 예시

```
[개념 이해] → [표로 정리] → [다이어그램으로 구조화] → [최소 예시로 확인]
```

## 예시 글

위 구조를 실제로 적용하면 이렇게 된다 (["Claude Agent SDK의 서브에이전트"](/posts/claude-agent-sdk-subagents/) 글을 요약 압축한 예시):

> **한 줄 결론**: 서브에이전트는 메인 에이전트의 컨텍스트를 오염시키지 않고 작업을 떼어 처리하는 "별도 창"이다.
>
> **비유**: 팀장이 모든 서류를 직접 다 보지 않고, 전문 담당자에게 서류 뭉치만 넘겨 요약 보고만 받는 것과 같다.
>
> | 용어 | 비유 | 설명 |
> |---|---|---|
> | 메인 에이전트 | 팀장 | 전체 작업을 조율 |
> | 서브에이전트 | 담당자 | 독립된 컨텍스트에서 세부 작업 수행 |
> | 핸드백 | 보고서 | 결과만 요약해 메인에게 전달 |
>
> ```
> [메인 에이전트] → [서브에이전트 호출] → [독립 컨텍스트에서 작업] → [요약 결과만 반환]
> ```
>
> **동작 원리**: 서브에이전트의 전체 도구 호출·중간 결과는 메인 에이전트 컨텍스트에 안 쌓이고, 최종 보고만 올라온다 — 그래서 메인 에이전트가 긴 작업을 여러 번 시켜도 컨텍스트가 덜 찬다.
>
> | 항목 | 내용 |
> |---|---|
> | 원칙 | 컨텍스트 분리로 긴 작업도 가볍게 |
> | 이유 | 중간 과정은 버리고 결과만 재사용 |

## 이 구조로 쓴 예시 글 (전체)

아래는 "캐시(Cache)"라는 주제로 위 7단계 구조를 처음부터 끝까지 그대로 적용한 완성형 예시다.

---

### 한 줄 결론

캐시는 "매번 계산하지 않고, 자주 쓰는 결과를 가까운 곳에 미리 보관해두는 것"이다.

### 비유

매번 창고(원본 데이터)까지 가지 않고, 자주 꺼내는 물건은 책상 위(캐시)에 올려두는 것과
같다. 책상이 좁아서(용량 제한) 오래 안 쓴 물건은 다시 창고로 치운다.

### 개념 표

| 용어 | 비유 | 설명 |
|---|---|---|
| 캐시 히트 | 책상에서 바로 찾음 | 캐시에 데이터가 있어 바로 반환 |
| 캐시 미스 | 창고까지 가야 함 | 캐시에 없어 원본에서 가져옴 |
| 캐시 무효화 | 책상 물건이 낡음 | 원본이 바뀌어 캐시를 지워야 함 |
| TTL | 책상 정리 주기 | 일정 시간 지나면 자동 삭제 |

### 구조 다이어그램

```
[요청] → [캐시 확인] ─히트→ [캐시에서 바로 반환]
                 └─미스→ [원본에서 조회] → [캐시에 저장] → [반환]
```

### 동작 원리

캐시가 빠른 이유는 디스크·네트워크 왕복을 건너뛰고 메모리에서 바로 읽기 때문이다. 다만
원본이 바뀌면 캐시도 같이 갱신하거나 지워야 하는데, 이 "언제 지울지" 판단(TTL, 이벤트
기반 무효화 등)이 캐시 설계에서 가장 어려운 부분이다.

### 최소 예시

```python
cache = {}

def get_user(user_id):
    if user_id in cache:
        return cache[user_id]  # 캐시 히트
    user = db.query(user_id)  # 캐시 미스 → 원본 조회
    cache[user_id] = user
    return user
```

### 요약 표

| 항목 | 내용 |
|---|---|
| 원칙 | 자주 쓰는 결과는 가까운 곳에 미리 저장 |
| 장점 | 응답 속도 향상, 원본 부하 감소 |
| 주의점 | 원본이 바뀌면 캐시도 반드시 무효화해야 함 |
