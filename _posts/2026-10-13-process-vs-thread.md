## TL;DR

프로세스는 "독립된 사무실", 스레드는 "그 사무실 안에서 같은 책상(메모리)을 쓰는 직원들"이다.
프로세스끼리는 서로의 메모리를 못 건드리지만, 스레드끼리는 같은 프로세스의 코드·데이터·힙을
공유한다 — 그래서 빠르지만 위험하다.

## 비유 한 줄

프로세스 = 독립된 사무실(자기 건물·집기 전부 소유), 스레드 = 그 사무실 안에서 일하는 직원
여러 명(같은 책상·캐비닛을 공유하되 각자 자기 업무 노트는 따로 둠).

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| 프로세스 | 독립된 사무실 | 메모리에서 실행 중인 프로그램, 코드·데이터·힙·스택을 전부 자기 것으로 가짐 |
| 스레드 | 사무실 안 직원 | 프로세스 안의 실행 흐름 단위, 모든 프로세스는 최소 1개(메인 스레드)를 가짐 |
| 스택(Stack) | 직원 개인 업무 노트 | 스레드마다 독립적으로 할당 — 함수 호출·지역변수 기록 |
| 코드/데이터/힙 | 사무실 공용 책상·캐비닛 | 같은 프로세스의 스레드끼리는 전부 공유 |
| 컨텍스트 스위칭 | 직원 교대 | 실행 중인 작업 상태를 저장하고 다음 작업 상태를 복원 |
| Critical Section | 공용 복합기 줄서기 | 공유 자원에 동시에 접근하지 못하게 막는 동기화 기법 |

## 구조 다이어그램

```
[프로세스 A]                    [프로세스 B]
┌─────────────────────┐        ┌─────────────────────┐
│ 코드 / 데이터 / 힙   │        │ 코드 / 데이터 / 힙   │  (서로 독립, 침범 불가)
│  ┌────┐  ┌────┐     │        │  ┌────┐             │
│  │스레드1│ │스레드2│     │        │  │스레드1│             │
│  │스택  │  │스택  │     │        │  │스택  │             │
│  └────┘  └────┘     │        │  └────┘             │
└─────────────────────┘        └─────────────────────┘
       ↑ 같은 프로세스 내 스레드는 코드/데이터/힙 공유
```

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 프로세스는 느리고 안전한가? | 메모리를 통째로 새로 할당하고 보호해야 해서 컨텍스트 스위칭 비용이 큼. 대신 한 프로세스가 죽어도 다른 프로세스엔 영향 없음 |
| 왜 스레드는 빠르고 위험한가? | 스택만 새로 할당하면 되니 전환이 가벼움. 대신 공유 메모리를 한 스레드가 망가뜨리면 같은 프로세스의 모든 스레드가 영향받음 |
| 왜 동기화가 필요한가? | 여러 스레드가 같은 데이터를 동시에 고치려 하면 레이스 컨디션이 생김 → Critical Section으로 "한 번에 하나씩"을 강제 |

## 예시

```python
import threading

counter = 0  # 모든 스레드가 공유하는 데이터

def increment():
    global counter
    for _ in range(100000):
        counter += 1  # 동기화 없이 여러 스레드가 동시에 건드리면 값이 어긋남

threads = [threading.Thread(target=increment) for _ in range(2)]
for t in threads: t.start()
for t in threads: t.join()

print(counter)  # 기대값 200000, 하지만 Lock 없이는 더 작게 나올 수 있음
```

## 요약 표

| 항목 | 프로세스 | 스레드 |
|---|---|---|
| 메모리 | 완전 독립 | 스택만 독립, 나머지 공유 |
| 생성/전환 비용 | 큼 | 작음 |
| 안전성 | 높음(격리됨) | 낮음(공유 자원 보호 필요) |
| 대표 사례 | 웹 브라우저의 탭 프로세스 | 하나의 서버 프로세스 안 요청 처리 스레드 풀 |
