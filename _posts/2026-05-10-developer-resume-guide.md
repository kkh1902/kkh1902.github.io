## 한 줄 요약

**이력서는 자서전이 아니라 면접 초대장**. 30초 안에 "이 사람 만나볼까?"가 결정된다.

## 채용 담당자가 30초 동안 확인하는 4가지

```
[이력서 받음]
   ↓ 5초    →  직군이 우리가 찾는 거랑 맞나?
   ↓ 10초   →  연차·기술스택 fit?
   ↓ 30초   →  이전 회사에서 뭘 만들었나?
   ↓ 1분~   →  (통과 시) 디테일 보러 정독
```

이 흐름을 알면 무엇을 위에 올릴지 자동으로 정해진다.

## 구조 (위에서 아래로)

| 섹션 | 분량 | 핵심 |
|---|---|---|
| **헤더** | 3줄 | 이름 / 연락처 / GitHub·블로그 링크 |
| **요약 (Summary)** | 2~3줄 | "X년차 Y 개발자, Z 도메인 경험" 한 문장 |
| **기술 스택** | 3~5줄 | 본인이 자신 있게 말할 수 있는 것만 |
| **경력** | 60% 분량 | 회사별 1~3개 핵심 프로젝트 |
| **프로젝트** | 신입·주니어 위주 | 실제 결과물 + 링크 |
| **학력·기타** | 3~5줄 | 짧게 |

A4 1~2장 권장. 5년 이하면 1장.

## 경력 한 줄 쓰는 공식 (STAR 압축형)

```
[무엇을] + [어떻게] + [결과 수치]
```

**나쁜 예:**
> 결제 시스템 개발 담당

**좋은 예:**
> Spring Boot 기반 결제 시스템 신규 설계 — 일 50만건 처리, p99 응답시간 200→80ms 단축

차이는 **수치**와 **선택한 기술**. "내가 이 결정을 했다"가 보여야 한다.

## 흔한 실수 5가지

1. **잘 모르는 기술 나열** — 면접에서 깊이 질문 들어오면 무너짐. 모르는 건 빼라.
2. **"~을 사용하여 ~을 개발"** 반복 — 동사가 단조롭고 결과 없음. 행동·결과 동사로 (구축·단축·증가·자동화)
3. **수치 없음** — "성능 개선" 보다 "응답 50% 단축"
4. **회사 소개를 길게** — 본인 한 일이 아님. 한 줄로 끝.
5. **모든 프로젝트 나열** — 핵심 3개. 나머지는 면접에서.

## 직군별 필수 요소

| 직군 | 추가로 보여줄 것 |
|---|---|
| 백엔드 | 트래픽·DB 규모, 장애 대응 사례 |
| 프론트엔드 | 실제 서비스 URL, 성능 지표(LCP·FCP) |
| 데이터 엔지니어 | 파이프라인 규모, 처리량, 비용 절감 |
| ML/AI | 모델 성능 지표(F1·AUC), 배포 환경 |
| DevOps/SRE | 인시던트 대응, 자동화로 줄인 시간 |

## 추천 도구

| 용도 | 도구 |
|---|---|
| 작성 | Notion, Google Docs, **마크다운 + 깃허브 액션 PDF 변환** |
| 디자인 | Canva, [Resume.io](https://resume.io), [JSONResume](https://jsonresume.org) |
| 점검 | 동료 1명 + ChatGPT로 "30초 안에 뭘 캐치했어?" 물어보기 |

## 마지막 체크리스트

- [ ] 30초 안에 "직군·연차·핵심성과" 다 보임
- [ ] 모든 항목에 수치 또는 구체적 기술 명시
- [ ] 동사가 다양함 (개발·구축·자동화·단축·증대…)
- [ ] 1~2장 분량
- [ ] 모르는 기술 안 적었음
- [ ] GitHub·블로그 링크 살아있음

이력서는 한 번 잘 만들면 끝나는 게 아니라 **분기마다 업데이트**해야 한다. 기억은 빨리 흐려진다.
