## TL;DR

정렬 알고리즘은 "카드를 줄 세우는 방법"이 다를 뿐 목표는 같다. 버블·선택·삽입은 쉽지만
느리고(O(n²)), 퀵·병합·힙은 "나눠서 정복(Divide and Conquer)" 또는 트리 구조를 써서
빠르다(O(n log n)). 실무/코딩테스트에서는 **퀵 정렬이 기본값**이지만 최악의 경우를
대비해 병합/힙을 대안으로 알아둬야 한다.

## 비유 한 줄

버블 정렬 = 옆 사람과 키를 비교해 한 칸씩 바꿔 서는 것(비효율적이지만 직관적).
퀵/병합 정렬 = 반 전체를 두 조로 쪼개 각자 줄을 세운 뒤 합치는 것(훨씬 빠름).

## 개념 표

| 알고리즘 | 비유 | 핵심 동작 | 시간복잡도(평균/최악) | 안정성 |
|---|---|---|---|---|
| 버블(Bubble) | 인접한 둘을 계속 비교해 교환 | 한 바퀴 돌 때마다 가장 큰 값이 끝으로 "떠오름" | O(n²) / O(n²) | 안정 |
| 선택(Selection) | 매번 제일 작은 사람을 찾아 앞으로 | 미정렬 구간에서 최소값을 찾아 맨 앞과 교환 | O(n²) / O(n²) | 불안정 |
| 삽입(Insertion) | 카드를 손에 들고 적절한 위치에 끼워 넣기 | 이미 정렬된 부분에 새 원소를 맞는 자리에 삽입 | O(n²) / O(n²) | 안정 |
| 퀵(Quick) | 기준값(pivot)보다 작은/큰 무리로 분반 | pivot 기준 분할 후 각 구간 재귀 정렬 | O(n log n) / O(n²) | 불안정 |
| 병합(Merge) | 반으로 쪼갰다가 정렬된 채로 합치기 | 더 못 쪼갤 때까지 분할 → 두 정렬된 리스트 병합 | O(n log n) / O(n log n) | 안정 |
| 힙(Heap) | 힙 트리에서 최댓값을 계속 뽑아내기 | 최대 힙 구성 후 루트를 꺼내 정렬 영역에 배치 | O(n log n) / O(n log n) | 불안정 |

## 구조 다이어그램

```
[버블/선택/삽입] — O(n²), 제자리(in-place), 구현 쉬움
   [8,3,5,1] → 인접 비교·교환 반복 → [1,3,5,8]

[병합 정렬] — 분할정복, 추가 메모리 O(n) 필요
   [8,3,5,1]
     ├─ [8,3] → [3,8]  ┐
     └─ [5,1] → [1,5]  ┴─ 병합 → [1,3,5,8]

[퀵 정렬] — 분할정복, pivot 기준 제자리 분할
   [8,3,5,1], pivot=5
     작은 무리[3,1] | pivot[5] | 큰 무리[8]
     각 무리를 재귀적으로 같은 방식 정렬

[힙 정렬] — 완전이진트리(배열로 표현) 이용
   배열 → 최대 힙 구성 → 루트(최댓값) 꺼내 맨 뒤로 → 힙 재구성 반복
```

## 동작 원리(왜?)

| 질문 | 답 |
|---|---|
| 왜 퀵 정렬이 평균적으로 가장 빠른데 최악은 O(n²)인가? | pivot을 잘못 골라(이미 정렬된 배열에서 항상 첫/끝 원소를 pivot으로 쓰면) 분할이 1:(n-1)로 치우쳐 재귀 깊이가 n이 됨 — 랜덤 pivot이나 median-of-three로 완화 |
| 왜 병합 정렬은 항상 O(n log n)인가? | pivot 선택이 없고 항상 반으로 "균등 분할"하기 때문에 최악의 경우가 없음. 대신 병합 과정에서 추가 배열(O(n))이 필요 |
| 왜 "안정 정렬"이 중요한가? | 같은 값을 가진 원소의 원래 순서를 보존해야 할 때(예: 이름순 정렬 후 나이순 재정렬) 안정 정렬이 아니면 결과가 뒤틀림 |
| 코딩테스트에서 뭘 쓰면 되나? | 대부분 언어 내장 정렬(Python `sort()`, Java `Arrays.sort()`)을 그대로 쓰면 됨 — 내부적으로 Timsort/듀얼 피벗 퀵정렬 등 최적화돼 있음. 직접 구현을 요구하면 퀵/병합이 출제 1순위 |

## 예시

```python
# 퀵 정렬 — 분할정복의 핵심만 담은 최소 구현
def quick_sort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    mid = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quick_sort(left) + mid + quick_sort(right)

print(quick_sort([8, 3, 5, 1, 9, 2]))  # [1, 2, 3, 5, 8, 9]
```

## 요약 표

| 상황 | 추천 알고리즘 | 이유 |
|---|---|---|
| 데이터가 거의 정렬돼 있음 | 삽입 정렬 | 최선의 경우 O(n)까지 빨라짐 |
| 안정성이 중요(동점 순서 보존) | 병합 정렬 | 안정 정렬 + 최악도 O(n log n) 보장 |
| 메모리 제약이 크고 평균 속도가 중요 | 퀵 정렬 | 제자리 정렬(공간 O(log n)), 평균 가장 빠름 |
| 최악의 경우도 보장해야 함(실시간 시스템) | 힙 정렬 | 항상 O(n log n), 추가 메모리 불필요 |
