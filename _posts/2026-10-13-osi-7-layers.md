## TL;DR

OSI 7계층은 "네트워크 통신을 7개 부서로 나눠 분업"한 설계도다. 각 계층은 자기 일만
하고 아래/위 계층과만 대화한다 — 그래서 한 계층(예: 와이파이→LTE)만 바뀌어도 나머지는
안 건드려도 된다.

## 비유 한 줄

택배를 보낼 때 "포장(물리)→주소 라벨(데이터링크)→동네 분류(네트워크)→택배사 선택
(전송)→실제 대화 세션 유지(세션)→번역/포맷(표현)→주문 내용 자체(응용)"처럼 역할이
나뉘어 있어서, 택배 상자 포장 방식이 바뀌어도 주문 내용 자체는 안 바뀐다.

## 개념 표

| 계층 | 비유 | 역할 | 대표 프로토콜/장비 |
|---|---|---|---|
| 7 응용(Application) | 주문서 내용 | 사용자가 보는 실제 서비스 | HTTP, FTP, DNS |
| 6 표현(Presentation) | 번역/포장 형식 | 인코딩·암호화·압축 | SSL/TLS, JPEG |
| 5 세션(Session) | 통화 연결 유지 | 연결 수립·유지·종료 관리 | RPC, 세션 쿠키 |
| 4 전송(Transport) | 택배사(신뢰 보장 여부) | 포트 기반 종단 간 전달, 신뢰성 | TCP, UDP |
| 3 네트워크(Network) | 우편번호로 동네 찾기 | IP 주소로 경로 찾기(라우팅) | IP, 라우터 |
| 2 데이터링크(Data Link) | 같은 동네 안 집 호수 찾기 | MAC 주소로 같은 네트워크 내 전달 | 이더넷, 스위치 |
| 1 물리(Physical) | 실제 도로·택배차 | 전기신호·광신호로 비트 전송 | 케이블, 허브 |

## 구조 다이어그램

```
[보내는 쪽]                    [받는 쪽]
7 응용        데이터 생성  ->                  7 응용
6 표현        암호화/압축  ->                  6 표현
5 세션        세션 관리    ->                  5 세션
4 전송        TCP 세그먼트 ->                  4 전송
3 네트워크     IP 패킷      ->                  3 네트워크
2 데이터링크   이더넷 프레임 ->                  2 데이터링크
1 물리        비트 신호    ->   [물리 매체]  ->  1 물리
                                (케이블/전파)
```

## 동작 원리(왜?)

| 질문 | 답 |
|---|---|
| 왜 7개나 나눴나? | 계층마다 책임을 분리하면 한 계층의 기술이 바뀌어도(예: 케이블→와이파이) 다른 계층 코드를 안 고쳐도 된다 — 관심사 분리(캡슐화) |
| 실제로는 왜 4계층(TCP/IP)으로도 설명하나? | OSI는 이론 모델이고, 실제 인터넷은 TCP/IP 4계층(응용/전송/인터넷/네트워크 접근)이 표준 — OSI는 교육·개념 정리용으로 더 많이 쓰인다 |
| 캡슐화는 왜 필요한가? | 각 계층은 상위 계층 데이터를 "그냥 내용물"로 취급해 자기 헤더만 덧붙인다 — 그래야 하위 계층이 상위 프로토콜 내용을 몰라도 전달만 할 수 있다 |

## 예시

웹 브라우저로 `example.com` 접속 시 계층을 타고 내려가는 과정:
```
7 HTTP GET 요청 생성
6 (HTTPS면) TLS로 암호화
5 TCP 커넥션(세션) 위에서 요청 전송 준비
4 TCP 세그먼트로 분할, 포트 443 지정
3 IP 패킷으로 캡슐화, 목적지 IP 라우팅
2 이더넷 프레임으로 캡슐화, MAC 주소로 다음 홉 전달
1 전기/광 신호로 실제 전송
```

## 요약 표

| 계층 범위 | 묶어 부르는 이름 | 핵심 질문 |
|---|---|---|
| 1~2 | 네트워크 접근 계층 | "물리적으로 어떻게 전달하나?" |
| 3 | 인터넷 계층 | "어디로 가야 하나?(라우팅)" |
| 4 | 전송 계층 | "신뢰성 있게 보낼까(TCP), 빠르게만 보낼까(UDP)?" |
| 5~7 | 응용 계층(TCP/IP 기준) | "실제로 뭘 주고받나?" |
