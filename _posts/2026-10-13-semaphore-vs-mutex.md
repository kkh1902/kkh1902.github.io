## TL;DR

뮤텍스는 "화장실 열쇠 1개"다 — 가져간 사람만 반납할 수 있고 동시에 1명만 들어간다.
세마포어는 "자리 N개짜리 공용 주차장"이다 — 카운터로 관리되고, 자리를 반납하는 사람이
꼭 그 자리를 처음 쓴 사람이 아니어도 된다. 둘 다 동시성 제어 도구지만 "소유권"과
"용도"가 다르다.

## 비유 한 줄

뮤텍스 = 화장실 열쇠 하나(상호 배제 전용, 가져간 사람만 반납 가능), 세마포어 = 숫자로
세는 공용 주차장 자리(동시 접근 허용 개수를 카운터로 관리, 누구나 반납 가능).

## 개념 표

| 용어 | 비유 | 한줄 설명 |
|---|---|---|
| 뮤텍스(Mutex) | 화장실 열쇠 1개 | 임계구역에 동시에 1개 스레드만 진입하게 하는 락, 소유권 개념 있음 |
| 이진 세마포어(Binary Semaphore) | 자리 1개짜리 주차장 | 값이 0/1뿐이라 뮤텍스와 비슷해 보이지만 소유권 개념이 없음 |
| 카운팅 세마포어(Counting Semaphore) | 자리 N개짜리 주차장 | 동시에 N개까지 접근 허용, 커넥션 풀 제한 등에 사용 |
| P 연산(wait) | 주차장 들어가기 | 카운터 감소, 0이면 대기 |
| V 연산(signal) | 주차장 나가기(자리 반납) | 카운터 증가, 대기 중인 스레드 깨움 |
| 소유권(Ownership) | 열쇠는 가져간 사람만 반납 | 뮤텍스는 잠근 스레드만 해제 가능, 세마포어는 아무나 V 호출 가능 |

## 구조 다이어그램

```
뮤텍스 (자원 1개, 소유권 있음)
[스레드 A] --lock()--> [임계구역 진입] --unlock()--> (A만 해제 가능)
[스레드 B] ... 대기 ...

카운팅 세마포어 (자원 N=3개, 소유권 없음)
카운터: 3 → 2 → 1 → 0 (4번째 스레드부터 대기)
[T1] P() [T2] P() [T3] P()  [T4] 대기...
      │        │        │
     V()      V()      V()  ← 아무 스레드나 반납 가능, 카운터 다시 증가
```

## 동작 원리 (왜?)

| 질문 | 답 |
|---|---|
| 왜 뮤텍스엔 소유권이 있는가? | 상호 배제가 목적이라 "누가 잠갔는지"가 중요함 — 다른 스레드가 실수로 풀면 임계구역 보호가 깨짐, 그래서 대부분 구현이 잠근 스레드만 해제를 허용 |
| 왜 세마포어엔 소유권이 없는가? | 상호 배제뿐 아니라 "신호(동기화)" 용도로도 쓰이기 때문 — 생산자가 P 없이 V만 호출해 소비자를 깨우는 생산자-소비자 패턴이 대표적 |
| 이진 세마포어와 뮤텍스는 뭐가 다른가? | 값만 보면 둘 다 0/1이지만, 뮤텍스는 소유권+우선순위 역전 방지(Priority Inheritance) 같은 안전장치가 있고 세마포어는 없음 — 그래서 상호 배제엔 뮤텍스가 더 적합 |
| 왜 카운팅 세마포어가 유용한가? | DB 커넥션 풀, 스레드 풀처럼 "동시에 N개까지만 허용"하는 자원 제한 문제를 카운터 하나로 깔끔하게 표현 가능 |

## 예시

```python
import threading

# 뮤텍스: 공유 변수 보호 (상호 배제 전용)
counter = 0
mutex = threading.Lock()

def increment():
    global counter
    with mutex:          # lock한 스레드만 자동으로 해제
        counter += 1

# 세마포어: 동시 접속 3개까지만 허용 (자원 제한)
pool = threading.Semaphore(3)

def access_resource(name):
    with pool:            # 카운터 감소, 0이면 대기
        print(f"{name} 자원 사용 중")
```

## 요약 표

| 항목 | 뮤텍스 | 세마포어 |
|---|---|---|
| 값의 범위 | 0 또는 1 | 0 이상 정수(카운터) |
| 소유권 | 있음(잠근 스레드만 해제) | 없음(누구나 해제 가능) |
| 주 용도 | 임계구역 상호 배제 | 자원 개수 제한, 스레드 간 신호/동기화 |
| 대표 사례 | 공유 변수 보호 | 커넥션 풀, 생산자-소비자 문제 |
